# Full-Stack Intern Assignment: "TaskFlow" — Mini Task Management App

## 🎯 Objective
Build a small, complete full-stack web application that lets users sign up, log in, and manage personal tasks (like a mini Trello/Todo app). This task is designed to test your understanding of frontend fundamentals, backend API design, database integration, and basic security/auth practices.

**Time expected:** 3–5 days
**Deliverable:** A GitHub repo link with clear setup instructions (README)

---

## 🧰 Tech Stack (Required)
- **Frontend:** HTML, CSS, JavaScript (vanilla — no frameworks like React/Vue for this task)
- **Backend:** Node.js + Express.js
- **Database:** Choose ONE:
  - MySQL (relational — good if you want to practice SQL/joins)
  - MongoDB (NoSQL — good if you want to practice document modeling)

> You're free to pick whichever database you're more comfortable with, or want to learn. Explain your choice briefly in the README.

---

## 📋 Functional Requirements

### 1. Authentication
- User can **register** with name, email, password
- User can **log in**
- Passwords must be **hashed** (use `bcrypt`)
- Use **JWT** for session/auth tokens (store in localStorage or httpOnly cookie — your choice, but explain it in README)
- Protect task routes so only logged-in users can access their own tasks

### 2. Task Management (CRUD)
Each task should have:
- `title` (required)
- `description` (optional)
- `status` (`todo`, `in-progress`, `done`)
- `priority` (`low`, `medium`, `high`)
- `dueDate` (optional)
- `createdAt`, `updatedAt`

User should be able to:
- ✅ Create a new task
- 📄 View all their tasks (with filter by status/priority)
- ✏️ Edit a task
- 🗑️ Delete a task
- 🔄 Mark task as complete/incomplete (quick toggle)

### 3. Frontend UI
- A clean login/register page
- A dashboard page showing tasks in a list or Kanban-style columns (by status)
- Form to add/edit tasks (modal or separate page — your choice)
- Basic responsive design (should work on mobile width too)
- Show loading and error states (e.g., "Failed to load tasks", spinners)

---

## 🔌 Backend API Requirements

Design and implement a **RESTful API**. Suggested endpoints:

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/auth/register` | Register new user |
| POST | `/api/auth/login` | Login, returns JWT |
| GET | `/api/tasks` | Get all tasks for logged-in user |
| POST | `/api/tasks` | Create a new task |
| PUT | `/api/tasks/:id` | Update a task |
| DELETE | `/api/tasks/:id` | Delete a task |
| PATCH | `/api/tasks/:id/status` | Toggle/update status only |

**Requirements:**
- Proper HTTP status codes (200, 201, 400, 401, 404, 500)
- Input validation (e.g., using `express-validator` or manual checks)
- Centralized error handling middleware
- `.env` file for secrets (DB credentials, JWT secret) — **do not commit this**, include `.env.example` instead

---

## 🗄️ Database Requirements

**If using MySQL:**
- Design a simple schema with `users` and `tasks` tables
- Use a foreign key (`user_id`) linking tasks to users
- Include a SQL file (`schema.sql`) to set up the database

**If using MongoDB:**
- Design `User` and `Task` collections/models (Mongoose recommended)
- Reference `userId` in each task document
- Include seed/sample data script (optional but nice to have)
